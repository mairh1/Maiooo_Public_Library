# MiMo 式通讯分享卡系统

## 1. 功能定位

只把本系统用于“把已有信息转成可转发图片”。功能上参考财经通讯类分享海报：自动组织标题、摘要、来源、时间和可选的真实跳转信息；设计上不采用财联社的红白品牌风格，而采用 MiMo 网站的暖中性色编辑设计。

功能参考：[财联社 APP 内容分享说明](https://www.cls.cn/detail/1343774)。该页面说明分享海报通常组合文章配图、标题、摘要和阅读全文入口。这里只借鉴信息组织功能，不复制品牌、颜色、二维码或版面。

MiMo 视觉参考：

- [MiMo V2.5 中文模型页](https://mimo.mi.com/models/zh-CN/mimo-v2.5)
- [MiMo 首页](https://mimo.mi.com/)

## 2. 信息结构

按以下顺序组织单张卡片：

```text
[类别标签]                         [日期 / 时间]

[标题：一句话说明发生了什么]

[正文摘要或 3–5 条要点]

[可选：关键数字 / 短结论 / 必要提示]

────────────────────────
[来源]                    [可选真实链接或二维码]
```

字段规则：

| 字段 | 必需性 | 建议长度 | 规则 |
|---|---|---:|---|
| 类别标签 | 可选 | 2–6 字 | 如“快讯”“公告”“行业”“研究摘要” |
| 标题 | 必需 | 12–30 字 | 优先写事实，不写悬念标题 |
| 正文 | 必需 | 90–220 字 | 保留主体、动作、数字和限定条件 |
| 要点 | 二选一 | 3–5 条 | 每条尽量控制在 18–36 字 |
| 关键数字 | 可选 | 1–3 组 | 必须带单位或口径 |
| 来源 | 推荐 | 1 行 | 严格照录，不推断 |
| 时间 | 推荐 | 1 行 | 使用用户提供的发布时间或数据期 |
| 二维码/链接 | 可选 | 1 个 | 只使用真实资产，绝不生成假二维码 |

## 3. 卡片选择

### 快讯卡

- 默认尺寸：1080 × 1350，4:5。
- 适用内容：单条新闻、公告、事件进展或产品动态。
- 结构：标签与时间、标题、单段正文、来源。

### 要点卡

- 默认尺寸：1080 × 1350；内容较长时用 1080 × 1920。
- 适用内容：政策要点、财报摘要、会议纪要或行业动态。
- 结构：标题、3–5 条编号要点、来源与时间。

### 数据卡

- 默认尺寸：1080 × 1080 或 1080 × 1350。
- 适用内容：一个核心数字、一组同比/环比或一项里程碑。
- 结构：标签、超大关键数字、短解释、口径、来源。
- 只把一个关键数字设为橙色；其余数字保持黑色或灰色。

### 系列摘要卡

- 封面卡只放标题、短导语和来源。
- 内容卡每张承载一个子主题或 3–5 条要点。
- 在右上角标记 `01/03`、`02/03` 等轻量页码。
- 最多默认生成 4 张；更多内容应进一步编辑，而不是无限延长系列。

## 4. MiMo 视觉系统

### 色彩

| 角色 | 色值 | 用法 |
|---|---:|---|
| 页面暖白 | `#FCFAF8` | 全卡主背景 |
| 卡片暖白 | `#FAF7F3` | 正文或数据模块 |
| 陶土灰 | `#F0EBE5` | 要点分区、引文或底部信息区 |
| 纯白 | `#FFFFFF` | 小面积提亮 |
| 主黑 | `#000000` | 标题、正文和主要数字 |
| 墨黑 | `#1A1A1A` | 柔和标题替代 |
| 次级文字 | `rgba(0,0,0,.55)` | 来源、时间、注释 |
| 暖边界 | `#E0D9D1` | 细分隔线 |
| 数据橙 | `#FF6A00` 至 `#FDA83A` | 唯一强调色，画面占比低于 5% |

不要引入第二种高饱和强调色。不要沿用财联社的红色品牌体系。

### 排版

- 使用 Inter、系统无衬线、思源黑体或同类中性字体。
- 保持 400–600 字重；正文不要使用细体，标题不要使用极粗黑体。
- 以 1080 px 宽画布为参考：标题 58–76 px，正文 32–38 px，元信息 22–26 px，行距约为字号的 1.45–1.65 倍。
- 默认左对齐；时间可右对齐；关键数字可单独放大。
- 保证正文区域每行约 18–26 个中文字符，避免超长行。
- 禁止使用图片生成模型直接生成正文文字。

### 空间与组件

- 四周安全边距使用 86–108 px，约为画布宽度的 8%–10%。
- 标题与正文之间留出一个明显停顿，不要连续堆满。
- 卡片分区使用陶土灰色块、1–2 px 细线或间距，不使用明显投影。
- 圆角保持克制；在 1080 px 画布上使用约 16–24 px 视觉圆角。
- 可在顶部使用一个 10–16 px 橙色方点或短线作为类别标记。
- 可在底部使用不超过画面高度 12% 的纯黑信息带，文字使用白色或 80% 白。

## 5. 内容压缩规则

1. 先提取“谁、何时、做了什么、关键数字、影响范围、信息来源”。
2. 删除重复背景、宣传性形容词和不影响结论的过程描述。
3. 保留所有限定词、时间区间、单位、统计口径和不确定性表达。
4. 不新增原因、影响或投资判断，除非原文明确给出。
5. 超过 220 字时优先改为要点卡；超过 5 个要点时拆成系列卡。
6. 标题只负责概括，不把正文所有信息塞进标题。

## 6. 渲染要求

- 优先使用 HTML/CSS、SVG、Canvas 或其他确定性排版工具生成最终卡片，再导出 PNG。
- 若需要装饰背景，可先用图片生成工具制作无字、低对比度的暖白几何底图，再叠加准确文字。
- 避免照片成为主角；只有用户提供的配图与内容直接相关时才使用，并将其裁成克制的小型模块。
- 不生成导航、按钮、App 截图、股票行情面板或复杂仪表盘。
- 不添加未经用户提供的品牌标志、媒体名称、版权声明或二维码。

## 7. 反例信号

- 只有一句口号，没有正文、来源或可验证信息。
- 画面像发布会 KV、广告海报、网页首屏或抽象 AI 插画。
- 文本由生成模型绘制，出现错字、乱码或不可读伪文字。
- 大面积红色、蓝紫霓虹、玻璃卡片、厚重阴影或装饰性粒子。
- 为塞下长文而缩小字号，导致手机端无法直接阅读。
- 仿造财联社、Xiaomi、MiMo 或其他媒体与品牌标识。

## 8. 最终检查清单

- 事实、数字、单位、语气、来源和时间与输入一致。
- 单张只传递一个中心结论。
- 标题、正文、重点与来源四层关系清楚。
- 正文字号适合手机阅读，信息不过载。
- 暖白、黑、暖灰为主，橙色只强调一个焦点。
- 无假二维码、假链接、伪造品牌或生成式错字。
