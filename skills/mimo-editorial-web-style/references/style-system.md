# MiMo 式编辑分享页系统

## 1. 功能定位

只把本系统用于“把已有信息转成可转发网页”。功能上参考财经通讯类分享海报的信息组织：自动组织标题、摘要、来源、时间和可选的真实跳转信息；交付形态为单文件 HTML 长页面，可选导出 PNG 截图。设计上不采用财联社的红白品牌风格，而采用 MiMo 网站的暖中性色编辑设计。

功能参考：[财联社 APP 内容分享说明](https://www.cls.cn/detail/1343774)。该页面说明分享海报通常组合文章配图、标题、摘要和阅读全文入口。这里只借鉴信息组织功能，不复制品牌、颜色、二维码或版面。

MiMo 视觉参考：

- [MiMo V2.5 中文模型页](https://mimo.mi.com/models/zh-CN/mimo-v2.5)
- [MiMo 首页](https://mimo.mi.com/)

## 2. 信息结构

按以下顺序组织页面，自上而下：

```text
[类别标签]                         [日期 / 时间]

[标题：一句话说明发生了什么]

[导语或单段正文]

[分节正文或 3–6 条要点]
    01  ……
    02  ……

[可选：关键数字 / 短结论 / 必要提示]

────────────────────────
[页脚：来源]              [可选真实链接或二维码]
```

字段规则：

| 字段 | 必需性 | 建议长度 | 规则 |
|---|---|---:|---|
| 类别标签 | 可选 | 2–6 字 | 如“快讯”“公告”“行业”“研究摘要” |
| 标题 | 必需 | 12–30 字 | 优先写事实，不写悬念标题 |
| 导语 | 可选 | 60–120 字 | 长文页用一句话交代背景与结论 |
| 正文 | 必需 | 每节 90–300 字 | 保留主体、动作、数字和限定条件 |
| 要点 | 二选一 | 3–6 条 | 每条尽量控制在 18–36 字 |
| 关键数字 | 可选 | 1–3 组 | 必须带单位或口径 |
| 来源 | 推荐 | 1 行 | 严格照录，不推断 |
| 时间 | 推荐 | 1 行 | 使用用户提供的发布时间或数据期 |
| 二维码/链接 | 可选 | 1 个 | 只使用真实资产，绝不生成假二维码 |

## 3. 页面类型

### 快讯页

- 适用内容：单条新闻、公告、事件进展或产品动态。
- 结构：页头（标签与时间、标题）、单段正文、页脚来源。
- 无分节，一到两屏内读完。

### 要点页

- 适用内容：政策要点、财报摘要、会议纪要或行业动态。
- 结构：标题、3–6 条编号要点、可选结论、来源与时间。

### 数据页

- 适用内容：一个核心数字、一组同比/环比或一项里程碑。
- 结构：标签、超大关键数字（唯一的橙色焦点）、短解释、口径、来源。
- 只把一个关键数字设为橙色；其余数字保持黑色或灰色。

### 长文页

- 页头只放标题、短导语和来源。
- 正文按子主题拆成编号分节，每节一个 `section`，配 01/02/03 编号或小节标题。
- 每节承载一个子主题或 3–6 条要点。
- 超过 5 节时应先编辑精简素材，而不是无限加长页面。

## 4. MiMo 视觉系统

### 色彩

| 角色 | 色值 | 用法 |
|---|---:|---|
| 页面暖白 | `#FCFAF8` | 全页主背景 |
| 模块暖白 | `#FAF7F3` | 正文或数据模块 |
| 陶土灰 | `#F0EBE5` | 要点分区、引文或页脚信息区 |
| 纯白 | `#FFFFFF` | 小面积提亮 |
| 主黑 | `#000000` | 标题、正文和主要数字 |
| 墨黑 | `#1A1A1A` | 柔和标题替代 |
| 次级文字 | `rgba(0,0,0,.55)` | 来源、时间、注释 |
| 暖边界 | `#E0D9D1` | 细分隔线 |
| 数据橙 | `#FF6A00` 至 `#FDA83A` | 唯一强调色，页面占比低于 5% |

不要引入第二种高饱和强调色。不要沿用财联社的红色品牌体系。

### 排版

- 使用系统字体栈：`-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", "Source Han Sans SC", sans-serif`；不引入外部或网络字体。
- 保持 400–600 字重；正文不要使用细体，标题不要使用极粗黑体。
- 响应式字号：标题 `clamp(28px, 6vw, 44px)`；小节标题 `clamp(20px, 4vw, 26px)`；正文 16–18 px；元信息 13–14 px；行高 1.6–1.75。
- 默认左对齐；时间可右对齐；数据页关键数字可单独放大到 `clamp(64px, 18vw, 120px)`。
- 正文区最大宽度 640–720 px，保证每行约 18–26 个中文字符，避免超长行。
- 禁止把正文文字做成图片，禁止用生成模型绘制文字。

### 空间与组件

- 移动端页面左右 padding 24–32 px；桌面端以居中栏方式自然放大留白。
- 标题与正文之间留出一个明显停顿，不要连续堆满。
- 分节使用陶土灰色块、1 px 细线或间距，不使用明显投影。
- 圆角保持克制：8–16 px。
- 可在页头使用一个 8–12 px 橙色方点或短线作为类别标记。
- 可在页脚使用纯黑信息带，高度不超过视口高度的 12%，文字使用白色或 80% 白。

## 5. 内容压缩规则

1. 先提取“谁、何时、做了什么、关键数字、影响范围、信息来源”。
2. 删除重复背景、宣传性形容词和不影响结论的过程描述。
3. 保留所有限定词、时间区间、单位、统计口径和不确定性表达。
4. 不新增原因、影响或投资判断，除非原文明确给出。
5. 单节超过 300 字时优先拆分节或改要点；超过 6 条要点时拆成多节。
6. 标题只负责概括，不把正文所有信息塞进标题。

## 6. HTML 技术要求

- 单文件交付：所有 CSS 内联在 `<style>` 中，断网双击即可正常显示。
- 必含 `<meta charset="UTF-8">` 与 `<meta name="viewport" content="width=device-width, initial-scale=1">`。
- 语义化结构：`<header>` 页头、`<main>` 正文、`<section>` 分节、`<footer>` 页脚。
- 不引用任何外部资源：无 CDN、无外链 CSS/JS、无网络字体、无外链图片。
- 不使用 JavaScript；页面为纯静态阅读页。
- 内容过长时拆分节，不为塞下长文而缩小字号。
- 若需要装饰，仅用 CSS 绘制低对比度的暖白几何元素；不添加未经用户提供的品牌标志、媒体名称或版权声明。
- 可选 PNG 导出：用户明确要求图片时，用浏览器打开 HTML 并整页截图导出 PNG，而不是用其他方式重新排版。

## 7. 反例信号

- 只有一句口号，没有正文、来源或可验证信息。
- 页面像营销落地页、产品官网、后台管理页或带按钮表单的 Web 应用。
- 依赖外部 CDN、网络字体或脚本，断网打开后样式崩溃。
- 出现编码乱码，或正文由生成模型绘制产生错字伪文字。
- 大面积红色、蓝紫霓虹、玻璃卡片、厚重阴影或装饰性粒子。
- 仿造财联社、Xiaomi、MiMo 或其他媒体与品牌标识。

## 8. 最终检查清单

- 事实、数字、单位、语气、来源和时间与输入一致。
- 单页传递一个中心主题；各分节各自承载一个子结论。
- 页头、正文、重点与页脚四层关系清楚。
- 正文不小于 16 px，手机端无需放大即可阅读。
- 断网打开正常：单文件、无外部依赖、UTF-8 无乱码。
- 暖白、黑、暖灰为主，橙色只强调一个焦点。
- 无假二维码、假链接、伪造品牌或生成式错字。
