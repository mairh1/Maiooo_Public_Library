# 通用可移植驱动框架——架构设计详解

`mcu-universal-driver` skill 的参考文档：解释十条硬约束背后的设计原理，给出具体做法与范例。约束正文见 [SKILL.md](../SKILL.md)；本文为深度参考，与正文冲突时以正文为准。

## 1 设计目标

驱动库的典型生命周期：单平台写好 → 多平台复用 → 被不同 RTOS / 裸机工程引用。决定复用成本的不是代码量，而是**硬件访问与协议逻辑的耦合程度**。框架目标：

1. 核心层在任何 C99 编译器上直接编译通过，零平台依赖
2. 移植成本 = 实现一份小契约（寄存器类 ≤8 函数；协议栈 / PHY 类按需，见 C3 分级）+ 按需改一个配置头，核心文件零改动
3. 多实例、线程安全、ISR 协作都有明确答案，不留「看代码才知道」

## 2 八条设计原则

| # | 原则 | 一句话 |
|---|---|---|
| P1 | 硬件无关核心 + 单向依赖 | 核心只知道「契约函数能读写、能延时」，不知道总线与 OS |
| P2 | 最小完备移植契约 | 必选函数压到 4 个左右，其余按配置可选 |
| P3 | 单头文件裁剪 | 配置集中一个 conf 头，`#ifndef` 默认值，`-D` 可覆盖 |
| P4 | 平台无关基础类型 | 只用 stdint/stdbool/stddef 固定宽度类型 |
| P5 | OS 服务钩子化 | 锁、延时全部走契约函数，核心不碰 RTOS API |
| P6 | 统一结果码 | 一个 result 枚举贯穿全部 API，错误语义分层 |
| P7 | 多实例无隐藏全局态 | 句柄由调用者分配，核心只有 `static const` 常量表 |
| P8 | 参考实现随库发布 | port 模板 + 平台示例，移植者照抄填空 |

### P1 硬件无关核心 + 单向依赖

依赖链严格单向：`应用 → 核心 → 移植层 → 硬件`，下层不得反向感知上层：

- `_io.h` 不 include 核心 `.h`——需要上下文时用 `void *io_ctx` 由调用者透传，移植层内部自行转换为目标句柄类型
- 移植层实现只 include `_io.h` 与平台头，不知道核心内部结构
- 核心对硬件的全部认知是「通过契约能完成寄存器读写与毫秒延时」；总线是 I2C、SPI 还是片上外设，由移植层翻译

这条原则的直接收益：换平台时协议逻辑一行不动；换芯片（同系列升级）时只改 regs.h 与少量档位表。

### P2 最小完备移植契约

契约函数按门控分两类：

| 类别 | 典型函数 | 门控 |
|---|---|---|
| 必选 | `io_init`、`io_read_reg`、`io_write_reg`、`io_delay_ms` | 无条件要求 |
| 可选 | `io_read_burst` / `io_write_burst`、`io_lock` / `io_unlock` | 对应 conf 宏置 1 才要求 |

关键规则：**关闭一个功能开关，对应契约函数一起消失**——裁掉突发传输后，不支持块传输的平台不再被要求实现它。这使「最小可用移植」恒等于必选集合。

每个契约函数的注释必须回答三问：

1. **返回什么**：返回码语义逐个列出
2. **时序怎么保证**：如「实际延时不允许小于请求值」「总线操作内部不得无限等待」
3. **什么上下文能调**：仅线程 / ISR 也可 / 两者皆可

### P3 单头文件裁剪

conf 头的宏分四类：

| 类别 | 示例 | 说明 |
|---|---|---|
| 功能开关 | `USE_BURST`、`USE_JEITA` | 置 0 联动裁剪 API + 实现 + io 契约 |
| 变体选择 | `VARIANT` | 硬件无法自识别的子型号由此指定 |
| 调试校验 | `VERIFY_WRITES`、`REG_SHADOW` | 用时间/内存换可靠性 |
| OS 选项 | `THREAD_SAFE` | 打开后引入 lock/unlock 钩子 |

全部写成 `#ifndef 默认值 #endif`，三种配置方式优先级从高到低：

1. 编译器 `-D` 覆盖（不改任何文件）
2. 工程私有 conf 放在 include 路径前面
3. 库自带默认值兜底

被裁剪 API 的处理二选一并写进 README：声明随 `#if` 消失（调用即编译报错，推荐），或保留声明返回 `ERR_NOT_SUPPORTED`（便于上层统一判错）。

### P4 + P5 平台无关与 OS 钩子化

- 类型只用 `<stdint.h>` 固定宽度类型 + `<stdbool.h>`/`<stddef.h>`；禁止依赖编译器内置类型、平台整型或 OS 头
- 禁止 `malloc/free`、VLA、递归；工作区全部由句柄或调用者承载
- 锁 → `io_lock/io_unlock` 钩子；延时 → `io_delay_ms` 契约；核心自身不出现任何 RTOS 符号
- 硬件等待循环必须带超时退出，超时路径返回明确结果码

### P6 统一结果码

一个枚举贯穿全部公共 API，标准语义集：`OK` / `ERR_IO` / `ERR_PARAM` / `ERR_NOT_READY` / `ERR_NOT_SUPPORTED`，可扩展 `ERR_VERIFY`、`ERR_TIMEOUT`。

分层含义：`ERR_IO` 只能来自 io 层失败的上抛；`ERR_NOT_READY` 表示器件侧未就绪而非通信故障。调用者可以按语义写统一的错误处理分支，而不是逐驱动适配。

### P7 多实例无隐藏全局态

- 句柄 `drv_xxx_dev_t` 携带 `io_ctx` + 设备标识（地址/片选/外设号）+ 运行状态（初始化标志、影子缓存等）
- 实例由调用者分配：全局变量、结构体成员、数组均可
- 核心层唯一允许的 `static` 是 `static const` 常量档位表；可变 `static` 即隐藏单例，直接封死多实例

### P8 参考实现随库发布

- `port/drv_xxx_io_template.c`：填空式移植模板，注释里给常见平台的写法示例
- `examples/<平台>/` 默认不创建（见 SKILL.md C10），演示用法在 README 给调用片段；用户明确要求时才编写完整示例
- README 的「已知坑」章节记录数据手册里的时序陷阱与硬件怪癖——这些是移植者最需要却最容易丢的信息

## 3 线程安全三级模型

| 级别 | 场景 | 保证方式 |
|---|---|---|
| L1 | 不同实例被不同任务并发访问 | 天然安全：实例状态全在各自句柄里，无共享可变状态（io 层若共享同一条总线，需总线自身线程安全） |
| L2 | 同一实例被多任务并发访问 | `THREAD_SAFE=1`，核心用 io_lock/unlock 包住读-改-写序列 |
| L3 | init/deinit 与运行时调用并发 | 文档明示不支持，由调用者保证时序 |

默认 `THREAD_SAFE=0` 并在 README 写明；锁的实现完全交给移植层（裸机关中断、RTOS 取互斥量均可），核心不感知锁的具体形态。

## 4 ISR 与异步事件模型

- 中断服务程序只置标志 / 计数（`volatile` 修饰），数据处理留在用户上下文
- 事件上抛两条路，驱动至少提供其一：
  - 轮询：`drv_xxx_get_events(dev, *events)` 返回并清除事件位图
  - 回调：`drv_xxx_set_event_cb(dev, cb, user_data)` 注册，回调在用户上下文执行，核心不直接在 ISR 里调用户回调
- 核心不得在 ISR 上下文调用延时类契约函数；契约注释注明哪些函数 ISR 安全

## 5 典型范例形态

### 寄存器类外部芯片驱动——标准五件套

```
<model>.h         公共 API：结果码 + 句柄 + 分组函数声明
<model>.c         核心：档位换算、影子缓存、时序封装
<model>_conf.h    功能裁剪（按芯片功能取舍：充电管理 / 影子缓存 / 校验写 / 线程安全等）
<model>_regs.h    寄存器位域定义
<model>_io.h      移植契约：init/read_reg/write_reg/delay_ms + 可选 lock/unlock
port/…_template.c 移植模板（含多平台注释示例）
README.md         分层图 + 移植三步走 + conf 表 + API 参考 + 已知坑
```

值得照抄的点：结果码语义分层；set 就近取整到硬件档位并钳位、get 返回实际生效值；「已知坑」章节把数据手册的时序陷阱显式交给调用者。

### 复杂协议栈驱动——事件回调模式

io 契约按需扩充到十几个函数，覆盖 PHY 收发、CC 检测、ISR 事件（对应 C3 的协议栈豁免）；`get_isr_events()` 把中断产生的事件以位图形式交还用户上下文处理，ISR 内只置标志——是 C9 异步事件模型的参考形态。

## 6 反模式清单

| 反模式 | 后果 | 对应约束 |
|---|---|---|
| 核心 .c 直接调 HAL / 厂商库 | 换平台重写整个驱动 | C1/C2 |
| 配置宏散落在 .c 里 | 移植要改库源码，升级即冲突 | C4 |
| 全局单例句柄写死在核心 | 第二片芯片没法接 | C7 |
| 返回 int/bool 混搭状态 | 调用者无法统一处理错误 | C6 |
| 契约函数缺时序/上下文说明 | 移植者靠猜，猜错即玄学 bug | C3 |
| 无 port 模板与示例 | 每个移植者从零开始踩坑 | C10 |
| 核心里出现无限等待循环 | 总线异常时系统挂死 | C5 |
