# WM8978 Rev 4.5 数据手册依据与取舍

本文只记录会影响驱动实现的规格书事实和矛盾。页码是 PDF 页面印刷页码。

## 已直接采用

| 事实 | 依据 | 驱动处理 |
| --- | --- | --- |
| 控制字为 B15:B9 地址、B8:B0 数据 | 第 82 页，Control Interface | 核心打包为两个字节，先 B15:B8 |
| MODE 低为 2-wire，高为 3-wire | 第 82 页，Table 63 | 物理模式由端口回调负责 |

## 规格书内部矛盾

### R10[6] SOFTMUTE

- 第 48 页同一区域的正文/Table 27 与第 95 页寄存器总表给出了相反极性。
- 仅凭当前 PDF 无法确定真实硅片语义。
- 驱动只定义 `WM8978_R10_SOFTMUTE_RAW`，不提供 `soft_mute(bool)`。
- 防爆音路径使用无歧义的 DAC 数字音量 0 和 R52-R57 模拟 MUTE 位。

### PLL N 范围

- 第 76 页正文写法可读作 `5 <= N <= 13`；同页 R36/Table 57 写明应大于 5 且小于 13。
- 驱动采用两种表述的保守交集 `6..12`。

### PLL K 示例末位

- 第 76 页 12 MHz 到 12.288 MHz 公式示例给出 `0x3126E9`；第 77 页 Table 58 给出 `0x3126E8`。
- 驱动不硬编码该表项，只接受调用者计算并验证的 24 位 K。

### ADCVU 交叉引用

- 第 96 页 ADCVU 说明文字把关联寄存器写成 16/17，但地址栏和第 35 页定义为 R15/R16。
- 驱动按地址栏、Table 69 和第 35 页使用 R15/R16。

### R27-R30 NFU 锁存行为

- 第 33、99 页把 `NFU` 描述为 Notch 系数内部更新标志，默认值明确写为 0；但没有像 VU/UPDATE 位那样明确标成 N/A 非锁存。
- 当前 PDF 因而不能严格证明 `NFU` 会自动清零。
- 为避免后续 `update_bits()` 因影子保留高电平而意外重复提交系数，驱动把 `NFU` 作为一次性请求：在线上发送 1，成功后在软件影子中清 0。
- 这是一项保守的软件策略，不声称是硬件读回值；需要使用 Notch 的项目仍应通过目标芯片验证系数更新行为。

## 不能由规格书单独确定

- 具体 CH32 SDK 的 I2C 地址参数是 7 位还是已左移 8 位；
- 具体板卡的 MCLK、I2S 引脚、DMA/IRQ、VMID 电容和电源时序；
- 软件复位写入后是否需要额外板级延时（本手册未给出明确时间）；
- 未列出/全保留寄存器被写入后的硅片行为。

因此驱动拒绝未列寄存器，不声称目标板级行为；具体工程必须通过 SDK 源码、原理图、逻辑分析仪和音频测试补足证据。
